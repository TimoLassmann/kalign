# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Kalign is a fast multiple sequence alignment (MSA) program for biological sequences (protein, DNA, RNA) written in C. CMake is the primary build system; Zig is an alternative for cross-compilation. Supported platforms are Linux and macOS (no Windows).

## Build Commands

### CMake Build (Primary)
```bash
mkdir build
cd build
cmake ..
make
make test
make install
```

Build types: `Release` (default), `Debug`, `ASAN` (`cmake -DCMAKE_BUILD_TYPE=ASAN ..`).

### Zig Build (Alternative)
```bash
zig build
```

## Testing

```bash
cd build
ctest            # all tests
ctest -R <name>  # one test
```

### Test targets (`tests/CMakeLists.txt`)
Executables registered with `add_test`:
- `kaligncpp` (test name `C++Lib`) - C++ API compatibility
- `kalign_ensemble_test` - accurate mode on BB11001 and BB40023 (consensus wider than 4096 columns)
- `kalign_api_test` - library API
- `poar_key_test` - POAR key handling
- `threadpool_test` - thread pool
- `dssim` (test `DSSIM_takes_a_min`) - distance similarity

Executables built but not registered as tests: `kalign_io_test`, `kalign_lib_test`, `kalign_cmp_test`, `largebench`.

Command-line tests run `kalign-bin` on the Balibase files in `tests/data/` (`kalign_itest_*`) or run CMake scripts: `preset_golden.cmake` (fast, accurate and the `default` alias on protein and DNA inputs must match golden SHA-256 values), `seq_type_cli.cmake`, `bad_input_cli.cmake`, `foreign_chars_test.cmake`, `deep_tree_test.cmake`. `kalign_threads_capped` checks the thread cap.

Python tests are in `tests/python/` and are not part of `ctest` (see below).

## Code Architecture

### Directory Structure
- `lib/` - Core library
  - `src/` - Library source (alignment, I/O, utilities)
  - `include/kalign/` - Public API headers
- `src/` - Command-line program
- `python-kalign/` - Python package (pybind11 bindings)
- `presets/` - Fitting code and results for the mode presets
- `perf/` - DP kernel harness and generators
- `tests/` - Test suite and data

### Two modes
Kalign 4 has two modes, selected with `--mode` (CLI) or `mode=` (Python):
- `fast` (default; alias `default`): a single alignment run.
- `accurate` (alias `recall`): a 5-member ensemble combined by a consensus, with per-column confidence. At most 5,000 sequences.

There are four fitted settings: protein and DNA/RNA, each for fast and accurate. They are in `lib/src/mode_presets.h`, which is generated from `presets/` by `presets/release/emit_c_presets.py`. Do not edit it by hand.

Options that change one alignment (gap penalties, VSM, guide distance) apply to fast only; ensemble options (`--fill-*`) apply to accurate only. The library entry points are `kalign_align_full` (every run passed explicitly) and `kalign_align_mode` (runs a named mode like the command line).

### Alignment Engine (`lib/src/aln_*.c`)
- `aln_seqseq.c`, `aln_seqprofile.c`, `aln_profileprofile.c` - scalar DP for sequence-sequence, sequence-profile and profile-profile
- `aln_wave.c` - wavefront SIMD DP (NEON or AVX2, via `wave_simd.h`), bit-identical to the scalar kernels. Generated by `perf/dp/tools/gen_aln_wave.py` from the kernels in `perf/dp/kernels/`; edit those and regenerate, not the C file.
- `aln_controller.c`, `aln_run.c` - alignment orchestration
- `aln_gapmodel.c` - gap model; `aln_vsm.c` - variable scoring matrix
- `bpm.c` - bit-parallel matching (Myers' algorithm)

### Ensemble and Consensus
- `ensemble.c` - runs the ensemble members
- `consensus_msa.c`, `consensus_fill.c`, `poar.c` - consensus alignment and confidence

### I/O (`lib/src/msa_*.c`)
- `msa_io.c` - reading and writing FASTA, MSF, Clustal
- `msa_alloc.c` - memory management for sequence data
- `msa_op.c` - sequence operations

### Guide Tree and Distances
- `sequence_distance.c`, `euclidean_dist.c`, `guide_dist.c` - distances
- `bisectingKmeans.c`, `sl_tree.c` - guide tree construction

### Utilities
- `tldevel.c`, `tlmisc.c` - development utilities
- `alphabet.c` - sequence alphabets (protein, DNA, RNA)
- `task.c` and `threadpool/` - threading: a work-stealing pthread pool. `-n 1` runs serially; the library caps the thread count at the number of cores.

### Performance Notes
- SIMD (SSE4.1, AVX, AVX2, NEON) is chosen at build time (`ENABLE_SSE`, `ENABLE_AVX`, `ENABLE_AVX2`). There is no run-time CPU detection: an AVX2 build needs an AVX2 CPU. Use `-DENABLE_AVX2=OFF` for older CPUs.
- Thread defaults: the command line uses (cores - 1), at most 16; the Python package defaults to 1 thread.
- Alignments must stay byte-identical unless a change is meant to alter results. Check this after touching DP, tree or consensus code.

## Python Module

The Python package is configured at the repository root (`pyproject.toml`, scikit-build-core and pybind11). It requires Python 3.11 or later; CI tests 3.11 to 3.14.

### Commands
```bash
uv pip install -e .                       # development install
uv run python -m build                    # build sdist and wheel
uv run pytest tests/python/ -v            # tests
uv run python -m cibuildwheel --output-dir wheelhouse
uv run python -c "import kalign; print(kalign.__version__); print(kalign.align(['ATCG','ATCGG']))"
```

Re-run the install after changing C or C++ code. To debug the extension with CMake, configure with `-DBUILD_PYTHON_MODULE=ON`.

### Package Structure
- `python-kalign/__init__.py` - high-level API (`align`, `align_from_file`, ...)
- `python-kalign/_core.cpp` - pybind11 bindings
- `python-kalign/cli.py` - `kalign-py` command
- `README-python.md` - Python documentation
- `tests/python/` - test suite

The low-level `_core` functions with per-run arrays are a development interface used to fit the settings. They are not part of the supported API.

### GitHub Actions
`.github/workflows/wheels.yml` builds wheels for Linux (x86_64) and macOS (x86_64 and arm64) with cibuildwheel, tests Python 3.11-3.14, and publishes to PyPI on tagged releases.
